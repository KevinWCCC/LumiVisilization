**t-SNE 图详细解释（针对您当前的可视化）**

### 1. t-SNE 是什么？它在图中代表什么？

**t-SNE**（t-Distributed Stochastic Neighbor Embedding）是一种**非线性降维算法**，专门用于把高维数据（这里是 2048 维的 embedding 向量）投影到 2D 平面上，同时尽可能**保留局部结构**（即原本在高维空间里距离近的点，在 2D 图里也倾向于靠近）。

- **横坐标 / 纵坐标**：没有任何物理含义，只是 t-SNE 算法为了可视化而人为构造的两个维度。**不能**把它们理解成“图像的横纵坐标”或“像素位置”。
- **点与点之间的距离**：只在**局部**有意义（perplexity 参数控制局部邻域大小）。全局距离（两个簇之间有多远）不可靠，这是 t-SNE 的典型局限。
- **颜色**：这是本图最关键的信息，下面详细说明。

### 2. 左图 (a) ASCII Tokens 的含义

- **每个点代表什么？**  
  LLM 原始 tokenizer 的 **输入 embedding 矩阵** 中，token ID 从 0 到 127 的那 128 个向量（对应早期词汇表中的 ASCII 字符、控制符、标点等）。

- **颜色如何对应？**  
  颜色直接映射到 **token ID 的数值**（0~127）。  
  例如：颜色条上标 0-19 的绿色点，对应 token ID 较小的 token；颜色条上 100-127 的青色点，对应 token ID 较大的 token。

- **图的含义**：  
  这些点分布得比较**分散、随机**，没有明显簇或流形结构。  
  这是正常的——tokenizer embedding 主要是通过海量文本的共现统计学到的，ASCII token 之间本身语义相似性不强（字母、数字、标点混在一起），所以在 embedding 空间里也没有强烈的拓扑结构。

### 3. 右图 (b) Numerical Tokens 的含义（最核心）

- **每个点代表什么？**  
  您自己实现的 `PixelInputEmbedding` 模块，对 **像素值 p ∈ {0, 1, ..., 255}** 做 forward 后得到的 2048 维向量。

  数学上：
  $$
  \mathbf{e}_p = \text{PixelInputEmbedding}(p) \in \mathbb{R}^{H}, \quad p = 0,1,\dots,255
  $$

  我们把这 256 个向量全部收集起来，做一次 t-SNE，就得到了右图。

- **颜色如何对应“输入的图”？**  
  **颜色 = 该点对应的原始像素值 p**（0~255）。  
  颜色条从蓝（低值 0-49）→ 黄 → 粉 → 青（高值 250-255）。

  **重要澄清**：这里**没有使用任何具体的输入图像**（比如 DIV2K/Kodak 的某张图）。  
  我们可视化的是 **PixelInputEmbedding 这张“查找表”本身** 的几何结构——即模型为所有可能的像素强度学到了什么样的 embedding。

  如果您在训练时输入一张真实图像，模型会把图像里每个像素的值 p 喂给 `pixel_emb(p)`，得到对应的 embedding 序列，再拼到 LLM 输入里。右图就是把这张“256 行查找表”在 2D 空间里展开后的样子。

### 4. 两张图对比的科研含义（对您 LUMI / PixelLLM 项目的意义）

| 维度           | 左图 (Tokenizer)          | 右图 (Pixel Embedding)              | 结论 |
|----------------|---------------------------|-------------------------------------|------|
| 结构           | 散乱、无明显流形          | 出现明显簇、环状/曲线结构           | Pixel Embedding 学到了**有意义的拓扑** |
| 相同颜色聚集   | 弱                        | 强（同色点倾向于聚在一起）          | 相近像素值被映射到相近的 embedding 空间 |
| 对图像建模的帮助 | 一般（文本先验）          | 更好（图像域先验）                  | 有利于后续 LLM 做更准确的概率建模 → 更低 BPP |

**您最想看到的结果正是右图的样子**：  
训练好的 `PixelInputEmbedding` 把 0~255 这条“数轴”在高维空间里“弯折”成了有结构的流形。这说明模型捕捉到了像素值之间的**相似性关系**（比如 50 和 60 比 50 和 200 更接近），这对无损图像压缩非常有利。

如果右图也像左图一样散乱，那就说明您的 Pixel Embedding 基本没学到东西（退化成了随机查找表）。

### 5. 解读 t-SNE 图时的注意事项（学术严谨性）

- **不能过度解读全局距离**：两个颜色差异大的大簇之间空得很远，不代表它们“完全不相关”。
- **对随机种子敏感**：换一个 `random_state`，图的旋转、形状可能略有不同，但**局部聚集性**通常是稳定的。
- **perplexity 参数影响**：您当前用 30，适合 256 个点；如果改成 5 会更强调极局部，改成 50 会看到更大尺度结构。
- **定量补充**：t-SNE 只是定性可视化。真正要论证 Pixel Embedding 的有效性，还需要看：
  - 训练/验证的 BPP 曲线
  - ablation study（去掉 INP、去掉 Pixel Embedding 后的 BPP 上升幅度）
  - 不同 pixel value 之间的 cosine similarity 矩阵是否与 |p_i - p_j| 相关
